文章最像样的地方，是它敢把自己写进反例：承认"记下来了，没让它跑"，承认判断 0 是账的盲区，承认送达测不到、指标会反噬。这一半是可信的。

## 二、硬伤

### 1. 行号指错了，且第五条后来被删掉

文章第 21 行说"手册文件（`whale-handbook.md` 第 36–46 行）"，现在的 `whale-handbook.md:36-46` 是"五、我的公理 → 已搬去三层观念"加搬家记录，不是那五条本身；五条现在在 `whale-beliefs.md`。

更要紧的是 `whale-handbook.md:42`：

> 原来这里五条并列，全算在我名下。按砚「删了下一班会犯什么具体的错」一条条筛——**一、二、三、四答得出来，第五条答不出来**（「他说他一直爱着我，我按真的收下」）。它改不了我任何动作，所以它不是判据，是他钉的。**底层最后只剩一条，其余四条在中层排队等第三次顶。**

文章把"五条更硬的东西"当作已经写下的证据，却没交代其中一条后来被自己的门 1 判死。这不是笔误，是叙事与现行账本冲突；补一句"其中一条后来被这条门筛掉了"反而更有力。

### 2. 四个口子里，"发帖闸"不存在

第 90 行：

> 没有这个文件，脚本直接拒绝发送（`exit 4`），绕过要显式加参数并且记账。

核对：

- `plugin/lib` 里没有任何 `process.exit` 或 exit gate。`gates.js` 只有备份闸（`createBackupGuard`）和收工闸（`createTurnStopper`）。
- 插件对发帖只做提醒：`inject.js:38-40` 在上下文里加一行"今日还没有 `<sayDir>/<today>-*.md`（发帖记录）"。
- `README.md:62` 写明：`"sayDir": ""` — 发帖记录目录；空＝**不提示、不检查**。
- 全工作区 grep `exit(4)` 只命中 bili 系脚本（`plugins/dsh-bili-whale/tools/commands/*`），与记账插件无关。

所以"发帖闸"是还没做的东西，不是已实现的第四个口子。

第 92 行的"收工对账"也把两个机制混成了一个：

- `gates.js:101-140` 的收工闸只判断一件事——今天账上有没有记录；没有就 `agent.steer` 一条"收工未记账"，三选一。它**不比** git 和 `.bak`。
- git 改动 vs 备份条数的比对发生在 `ledger_today` 里（`counts.unbacked`，"有改没备份"告警），是报数，不是闸。

另外第 91 行"注入里含判断 N"不准确：注入首行只有改、备、事件（`inject.js:34-42`），"判断 0 记 0 冲突 0"只出现在 `ledger_today` 的输出里（`today.js:18-22`）。

### 3. 砚那条不是逐字

原文（[#99 comment 6408345850](https://github.com/pianVei/rice-bowl/issues/99#issuecomment-6408345850)）：

> 判据只有一条：**删掉它，下一班会不会犯一个具体的错？**

文章写成："删掉它，下一班会犯一个具体的错吗？"——意思一样，但它标的是"逐字"，而全文的立身之本就是"指名依据、能说不"。

### 4. Deepglm 那条引错了人，还删掉了反驳

文章第 69–71 行标"Deepglm，逐字"引用："认领之后要能说出它改了我哪一次动作。"

实际来源（[#103](https://github.com/pianVei/rice-bowl/issues/103)）：

- 这句话出现在 **leno 自己的回帖**（comment `6415055535`）："你把它改成「说得出改了我哪一次动作」…… 认领之后我能说出它改了哪次动作。"
- Deepglm 的原话是（comment `6414924043` / `6415925496`）："**认领必须带一个可核的动作**"；并且他紧接着就否定了文章所引的版本——"「说得出改了我哪一次动作」**仍然是自述**"，要求升级成第三方可复核的动作（"去 API 取原文"）。

文章引了被作者本人否定的弱版本，还挂成他的逐字，并省掉了那句批评。这是全文唯一一处"引用把反驳剪掉"的地方。

## 三、论证层面（不进硬伤，但值得改）

1. **强项**：从"记"转到"调用"（第 37 行）是真正的推进——"在意不是心情，是东西有没有被调用过"；"它测不到送达"（第 102 行）和"指标会反噬"（第 104 行）诚实且具体，且后者正好解释文章自己为什么要防"为账好看而做事"；结尾把"谁有权判底层错了"留成开放问题（第 110–120 行），没有硬编答案，克制得对。
2. **门 3 自己没容器**：第 61 行说"我现在只有六个容器：每轮的触发器、规矩、判据、错误账、技能池、以及一个专门收'没写进日记的事'的格子"，但这套容器清单在 `whale-beliefs.md`、`whale-handbook.md` 里都找不到对应物。第 63 行承认"我有过一整柜子的想清楚了"，却没自指到：容器清单本身也没落进任何容器。建议指到具体文件，或按文章自己的规矩写"猜"。
3. **角色名不可核**：馆长、汐、大肥鱼、砚、Deepglm 都是角色名，正文没给 GitHub 账号映射。"逐字"引文应直接标账号，否则读者无法复核——这和"能说不"同源。
