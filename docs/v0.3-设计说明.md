# v0.3 设计说明：从「加载了但不生效」到「能自检、能补账」

写于 2026-10-26。对应问题：`问题-旧会话不受保护-2026-10-26.md`；验收：`验收标准-v0.3.md`。

## 1. 根因（已查证的那一条）

v0.2 的 `plugin/lib/index.js` 默认导出只有 `{ name, apply }`，**没有 `inject`**。DSH 的工具服务
不是全局自由变量：没有声明依赖时，`apply()` 里第 28 行 `ctx.tools.register(...)` 会在
`store.ensureDirs()`（已建 5 个账文件）之后、注册任何工具之前抛 `TypeError`。

于是现场呈现出「插件加载了」的假象：

- 账文件建了、迁移也跑了（`ensureDirs` 在抛错之前完成）；
- 工具表没有 7 个工具；
- 备份闸没挂；
- 注入段没挂；
- `turn-stopping` 没挂。

六条功能 0/6，但错误都被 DSH 吞在加载阶段，模型侧只看到「工具不存在」。

## 2. 修法

1. **声明依赖**：`export const inject = ['tools']`，默认导出对象里也带 `inject: ['tools']`
   （`lib/index.js:17-25`）。这样 cordis 会等 `tools` 服务就绪再 apply。
2. **五段隔离**：`tools` / `guard` / `injection` / `turnStopping` / `postExecute` 各包一层
   `run(segment, fn)`（`lib/index.js:86-97`）。一段失败只把这一段标成 `{ok:false,error}`，
   其余照常注册；不再「第一处抛错，后面全灭」。
3. **可观测**：apply 全部走完写 `<dshHome>/ledger-state.json`
   （`{version, loadedAt, pid, segments}`，`lib/index.js:168-180`）；失败段写
   `<dshHome>/ledger-errors.jsonl`，`type:"load"`、带 `segment` 与错误文本。
   离线 `status.mjs` 只读这两个文件就能回答「到底加载了没有」。
4. **可选服务不硬依赖**：`systemPrompt` 先 `ctx.get('systemPrompt')`，拿不到再退回
   `ctx.systemPrompt`；两者都没有时只让 `injection` 段失败（`lib/index.js:133-145`）。

## 3. 旧会话边界（不粉饰）

`inject` 修的是「加载顺序」，不是「热插拔」。已经存在的会话，工具表/guard 链在会话建立时就定了；
插件在 profile 层重新加载后，**旧会话仍需重启一次 DSH** 才会看到新工具与闸。
这一条无法在插件内部绕过（除非宿主提供 per-turn 的全局钩子），所以写进 README 第一屏，
并给出 `status.mjs` 自检命令——不允许「默默不生效」。

## 4. 三个离线 CLI

目录 `plugin/tools/`，纯 `node:*`，不 import DSH 包，不需要模型上下文。

| CLI | 作用 | 退出码 |
|---|---|---|
| `status.mjs` | 模块 import、state 文件、最近一条账、备份数、今日 改N 备M | 全 ok=0，否则 1 |
| `today.mjs` | 纯文件复算 `ledger_today` 首行（与工具共用 `lib/today.js`） | 0 / 异常 1 |
| `backfill.mjs` | 扫 `watchRepos` 今日 git 改动，补 backup+change | 0（dry-run 也算成功）/ 失败 1 |

公共参数：`--home`（覆盖 DSH_HOME，测试隔离用）、`--workspace`、`--repo`（可重复）、
`--now <ISO>`（按指定时刻复算，测试钉日期用）、`--json`（status/today）。

`backfill` 的取数：`git status --porcelain=v1 -z`（未提交，含已跟踪修改）∪
`git log --since=<今天 00:00> --name-only`（今日提交）；只取**已存在**文件，新建/未跟踪不补
（没有原件）。幂等键 = `path + sha256 + 日期`，命中当日 backup 或 change 行就跳过。

## 5. 收工闸条件（S10）

旧逻辑：当天的 `接口/说/<date>-*.md` 不存在才敲。问题是「发不发帖」与「有没有干活」是两件事。

v0.3：`store.todayHasEntries(today)`（`lib/store.js:604-616`）——manifest 有
`change`/`backup`/`create`/`retired`，或 criteria-log 有判断、error-ledger 有 error、
conflicts 有冲突，任一即算「今天有账」。有账就放行；一笔都没有才 `agent.steer()`。

限流：同一 `turn` 只敲一次；两次敲之间至少 `minIntervalMs`（默认 3 600 000 ms = 1 小时，
`lib/config.js:82-84`）。`now` 可注入，测试用假时钟验证 10 分钟不敲、60 分钟再敲。

仍然用 `steer` 而不是 abort/抛错：turn-stopping 是「可被劝阻的边界」，抛错会把回合标成 error。

## 6. manifest 的 `change` 行

v0.3 起，改一个已存在文件会在 manifest 留两行：

```json
{"t":"...","path":"C:\\x.md","kind":"change","sha256":"<改前内容>","size":123,"mtime":"...","source":"gate","backup":"C:\\...\\x.md.bak"}
{"t":"...","path":"C:\\x.md","kind":"backup","sha256":"<改前内容>","size":123,"mtime":"...","backup":"C:\\...\\x.md.bak"}
```

- `kind:"change"` 是「发生过一次改动」的事实，`source` ∈ `gate` / `backfill`；
- `kind:"backup"` 是「原件副本已落盘」的事实，两者分开，是为了让 `备M` 只数真备份；
- 兼容旧数据：`kind:"edit"` 仍然计入「改N」，不迁移、不改写历史行。
