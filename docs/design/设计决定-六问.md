# 设计决定：六个疑问的处置方案

> 本节是审核员（主智能体）对规划书自检六问的回答。代码员须按此实现；
> 技术报告第③章必须**完整收录**本文件，并逐条标注"已实现/部分实现/未实现 + 落点文件行 + 测试名"。

---

## 问 1：错误账没有对应的 `ledger_*` 工具

**方案**：新增第 7 个工具 `ledger_error`。
- 参数：`text`（必填）、`source`（记错来源，如 `"ledger_today"`）、`level`（`P0|P1|P2`，默认 `P1`）、`ref`（相关文件/行号，可选）。
- 写入 `whale-error-ledger.jsonl`，每行 `{t, text, source, level, ref}`。
- `ledger_today` 首行末尾追加聚合：未结错误 ≥3 条时显示 `⚠错误N`。
- 结论：规划书里"错误账"只有文件没有工具，属于漏项，用第 7 个工具补齐，不做隐藏副作用。

## 问 2：怎么计量"规矩被调用"

**方案**：不做行为检测（不可靠、易误判），改为**显式引用计量**。
- `ledger_judge` 增加 `rule` 参数（规矩 id，如 `发一条之前`）；每次下判断时记录 `whale-rule-usage.json`：`{rule: {n, last}` 与 `whale-criteria-log.jsonl`。
- `ledger_today` 显示"近 7 天被引用 0 次的规矩数"。
- **诚实边界**（必须写进报告）：这只统计"显式写了规矩 id 的判断"，不统计"心里想过没写"。所以只能降级为"引用率"指标，不能声称"规矩真被遵守"。

## 问 3：验收指标 4（7 天没被调用的规矩要简化）可被"退休刷低"

**方案**：规矩只许**合并**或**标记取代**，不许无痕删除。
- `ledger_belief` 增加操作 `retire`（退休）：必须带 `successor`（取代它的规矩 id）或 `mergeInto`；同时往 manifest 写 `kind: retired` 事件。
- 验收指标改为：**"7 天引用 0 次 且 未被标记取代"的规矩数**。退休但无 successor 的，单独列为"孤儿规矩"并报警。
- 效果：刷指标的唯一方式是把规矩真合并掉，而合并本身留下痕迹。

## 问 4：备份去重与"漏备"无法区分

**方案**：manifest 每条记录 `path + sha256 + size + mtime + kind`，用指纹而非路径判重。
- **去重**：同 path、同 sha256、当日已存在 → 返回 `dedup: true`，闸门放行。
- **漏备**：当日 manifest 无该 path 的任何记录 → 拒绝。
- **改过再改**：sha256 变化 → 视为新版本，必须再备（同一文件当日第 2 次修改仍要备份，不因"今天备过"而放行）。
- 结论：两者由 sha256 天然区分，不需要额外标记。

## 问 5：每轮注入变成噪声

**方案**：只注入"仍然成立且有信息量"的内容。
- 只取未做账中 7 天内新增的，最多 5 条，每条截断 20 字；
- 已注入过的记 `last_injected`，24h 内不重复注入同一条；
- 三项都正常（无未做、今日有事件、错误<3）→ 返回空段，系统提示里自动消失（S19）。
- 注入位置固定在尾部段（order ≥ 9000），不碰前缀，避免破坏缓存（S18）。

## 问 6：`--no-event` 逃生阀太方便，等于没有闸

**方案**：给逃生阀上三道锁。
1. 每次跳过都必须写错误账（`type: skipped-check`），可见、可数；
2. **每自然日最多 1 次**跳过；第 2 次仍无事件 → 拒绝收工，reason 提示"要么记账，要么改规矩"；
3. 阈值可配置（`maxSkipsPerDay`，默认 1），写进配置与报告。
- 结论：允许一次例外（真实场景需要），但不允许把例外变成常态。
