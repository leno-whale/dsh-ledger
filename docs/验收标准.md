# 验收标准 v0.3（旧会话不受保护 → 可交付版）

依据：`问题-旧会话不受保护-2026-10-26.md` 五个诉求 + 主人 m00580 的交付要求（git 分支上的完整插件 + README）。
执行方式：子智能体写代码并自测；我按本表逐条验收；通过后才推 git 分支。

## A. 根因与加载

- S1 插件定义带 `inject: ['tools']`；`systemPrompt` 用可选方式（`ctx.get('systemPrompt')` / 方法存在性判断），不再假设 `ctx.tools` 一定存在。
- S2 `apply()` 内各段（tools / guard / 注入 / turn-stopping / post-execute）逐个 `try/catch`，一段失败不影响其余；失败写 `~/.dsh/ledger-errors.jsonl`，`type:"load"`，含 `segment` 与错误文本。
- S3 `apply()` 全部走完后写 `~/.dsh/ledger-state.json`：`{ version, loadedAt, pid, segments: {tools, guard, injection, turnStopping, postExecute} }`；某一层失败时该项为 `{ok:false, error}`。

## B. 旧会话保护（本次核心）

- S4 备份闸是全局 guard（不绑单个 agent 的 ctx），对**已存在会话**下发起的 `write`/`edit` 同样生效。
- S5 部署后实测（由主人在真实会话执行，不由代码员做）：改一个已存在文件 → `~/.dsh/backup` 新增一份、`ledger-manifest.jsonl` 新增一行 `change`+`backup`；改新文件 → 无需备份。
- S6 若宿主确实做不到热挂，README 第一屏必须明写「旧会话需重启一次 DSH 才生效」，并给出 `status.mjs` 自检命令；不得默默失败。

## C. 离线 CLI（不需要模型上下文）

- S7 `plugin/tools/status.mjs`：打印 ①插件模块能否 import ②`ledger-state.json` 是否存在及内容 ③最近一条账（时间/type/摘要）④备份目录文件数 ⑤今日「改N 备M」。任一异常给可读提示；正常退出码 0，异常 1。
- S8 `plugin/tools/backfill.mjs`：扫 `watchRepos` 今日 git 改动过、且今日无对应备份的已存在文件，补 `backup` + `change`（`source:"backfill"`）；默认 `--dry-run` 只打印将补的清单，`--apply` 才写；幂等（重复跑不重复补）。
- S9 `plugin/tools/today.mjs`：纯文件复算 `ledger_today` 一行：`改N 备M | 判断N 记M | 冲突N | 今日事件：有/无`，与工具输出一致。

## D. 收工闸条件

- S10 `agent/turn-stopping` 触发条件改为「**今天账上一笔都没有**」（change/backup/judgment/error/conflict 任一即算有），不再以「事件文件」为准；仍遵守 `minIntervalMs`（默认 1h），同一轮不重复敲。

## E. 测试与文档

- S11 `node --test` 全绿；新增：status/backfill/today 的 CLI 测试（临时 HOME，不触碰真实 `~/.dsh`）、apply 分段容错测试（缺 `ctx.tools` 时其余段仍注册）、state 文件写出测试。
- S12 README 重写：安装/升级/自检/旧会话说明/三个 CLI 用法/数据格式/已知限制（诚实写清做不到的部分）。
- S13 版本号 `0.3.0`；`plugin/package.json` files 含 `tools/`。

## G. 纪律

- S18 不修改 `~\.dsh` 下真实账本/备份（测试一律临时目录）；不改 profile 的 `package.json`（部署由主人决定）。
- S19 未通过项如实标注「未验证」并写原因，不许用 mock 通过冒充真实通过。
- S20 **测试命令必须是别人会走的那一条**：跑 `npm test`（CI 跑的就是它），不许只跑手敲的变体（`node --test test/*.test.js`）。
  来历：2026-10-27 CI 连红两次、只挂 node 22 —— 因为 `plugin/package.json` 里残留 `--test-isolation=none`（Node 23+ 才有），而本地一直手敲 glob，于是"我验过"和"CI 会跑"成了两回事；顺手还发现手敲的 glob 漏掉一个测试文件（91 vs 92）。
  同族：S3 的分段容错、S19 的"不许 mock 冒充"——都是**验的要和跑的是同一条路**。
