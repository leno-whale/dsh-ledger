## 1. 数据层

- **S1 路径可移植**：所有数据路径经 `DSH_HOME`（默认 `~/.dsh`）解析，**禁止**硬编码 `C:\Users\HUAWEI`。测试用临时 `DSH_HOME` 隔离。
- **S2 六类文件齐备**：`whale-conflicts.jsonl`、`whale-backup-manifest.jsonl`、`whale-error-ledger.jsonl`、`whale-criteria/<id>.md`、`whale-rule-usage.json`、`whale-criteria-log.jsonl`，每行一条 JSON，字段含 `t`（ISO 时间）与语义字段。
- **S3 不毁旧数据**：对既有 `whale-beliefs.md`、`whale-beliefs-log.jsonl`、`whale-undone.jsonl` **只追加/只读**；任何写都必须"先备份→tmp 写→rename"原子落地，中断后不留半文件。
- **S4 损坏容错**：任一文件被截断/非法 JSON 时，插件不崩溃：跳过坏行、写错误账一条、继续工作。

## 2. 工具层

- **S5 工具名与 schema**：注册 7 个工具 `ledger_today / ledger_undone / ledger_conflict / ledger_judge / ledger_belief / ledger_backup / ledger_error`。每个 description ≤2 句且写明"何时调用"；parameters 完整；execute 返回结构稳定。
- **S6 ledger_today 输出有硬上限**：≤20 行、≤800 字符；首行固定格式 `改N 备M | 判断N 记M | 冲突N | 今日事件：有/无`。
- **S7 ledger_backup 语义**：路径不存在 → 返回错误（不静默成功）；同路径同 sha256 当日已备 → 标 `dedup: true`；否则复制到 `backup/<YYYY-MM-DD>/<name>.bak` 并追加 manifest（含 `path/sha256/size/mtime/kind`）。
- **S8 入参校验**：路径解析为绝对路径；`ledger_judge` 的 A/B/C 编号匹配 `^[ABC]\d+$`；`ledger_error` 的 `level` ∈ `{P0,P1,P2}`。
- **S9 不回灌全文**：任何工具返回体不得包含被读文件全文（防撑爆上下文）。

## 3. 闸门（硬闸，M2 必做）

- **S10 备份闸**：拦截 `write`/`edit`（如不存在 multi_edit 则只拦这两者）。目标文件**已存在且 size>0** 时，查当日 manifest 是否有该路径备份；无 → 拒绝。拒绝理由字符串必须同时含：`leno-ledger: 未备份`、规范化绝对路径、以及可直接复制的补救调用 `ledger_backup` + 参数。
- **S11 自动备份模式**：`autoBackup` 默认 `true`——闸门先备份再放行（不阻断），并在返回内容里提示已备份；设为 `false` 时改为硬拒绝。两种模式的默认值必须写进报告。
- **S12 新建文件放行**：目标不存在 → 放行，但 manifest 记一条 `kind: create` 事件。
- **S13 发帖闸**：若本环境无"发帖"工具，则退化为对 `ledger_judge` 的四问必填校验，并在报告"实现落点"栏写明替代方案（规划书中的 say.mjs 路径仅作集成测试目标，不硬依赖）。
- **S14 收工闸**：在回合结束的生命周期点（`agent/turn-stopping` 或等价点）检查当日是否存在 `接口/说/<date>-*.md`；不存在且未带跳过标记 → 取消收工，reason 含 `leno-ledger: 收工未记账` 与下一步动作。跳过标记必须写错误账（`type: skipped-check`）。
- **S15 闸门不静默失败**：闸门内部异常一律 **放行** + 写错误账，并在报告"已知缺陷"列明。禁止因插件 bug 卡死用户。
- **S16 只拦不猜**：闸门只判断"做没做"，不判断内容对错、不校验文风。

## 4. 注入

- **S17 每轮注入 ≤5 行**：最新未做（每条截断 20 字）+ 今日改/备计数 + 今日事件有/无；仅在有内容时注入。
- **S18 不破坏前缀稳定**：注入只能经 `ctx.systemPrompt.section`（order ≥ 9000 的尾部段）或 runtime context，**禁止**插入前部或改写既有段；实测影响写入报告。
- **S19 空则消失**：一切正常时返回空字符串段，不刷屏、不制造噪声。

## 5. 可测性

- **S20 单测覆盖**：备份去重、manifest 追加、闸门拒绝/放行、损坏容错、`DSH_HOME` 隔离、原子写中断（tmp 残留检查）。
- **S21 mock-ctx 集成测试**：假 ctx（实现 `tools.register`、`tools.guard`、`on`、`effect`、`systemPrompt.section`）调用 `apply()`，断言：工具数=7、guard 已注册、对已存在文件 `write` 会先产生备份。
- **S22 不污染真实数据**：全部测试跑在临时 `DSH_HOME`；跑测前后对 `~/.dsh` 关键文件做 size+mtime 快照并比对。

## 6. 技术报告

- **S23 必备章节**：①实现概览与文件树 ②每道闸门的触发/不触发条件（表格）③六问方案（完整收录 `设计决定-六问.md` + 实现落点 + 已验证/未验证）④测试命令与输出摘要 ⑤已知缺陷与未做（诚实清单）⑥部署/卸载步骤。
- **S24 无空口结论**：每条"已实现"须能溯源到测试名或文件行；无法测试的写"未验证"。
- **S25 卸载干净**：所有注册（工具、guard、listener、定时器）都挂在 `ctx.effect`/disposer 上，插件停用后零残留行为。

## 7. 边界纪律

- **S26 不碰旧文件**：不改动 `F:\agent expore` 下既有目录与文件（`接口/`、`plugins/`、根目录 `*.md`）；一切新增产物只在新文件夹内。
- **S27 不启动新服务、不改 profile**：部署步骤写进报告，由用户决定是否执行；**不得**擅自修改 `C:\Users\HUAWEI\.dsh\profiles\desktop\package.json`。
- **S28 环境**：Node 22+、ESM、零外部依赖、零网络。
