- 运行环境：Windows + Node v24.22.1（要求 ≥22）

## ② 每道闸门：触发 / 不触发条件表

### 2.1 备份闸（拦 `write` / `edit`）

| 条件 | 行为 | 落点 |
|---|---|---|
| 工具不是 `write`/`edit` | 放行 | `gates.js:20` |
| `file_path` 为空或非字符串 | 放行（交给原工具报错） | `gates.js:23` |
| 目标不存在 | 放行，manifest 记 `kind:create` | `gates.js:26-29` |
| 目标存在但 `size===0` 或不是普通文件 | 放行，不备份 | `gates.js:32` |
| 当日已有同 path + 同 sha256 的 `kind:backup` | 放行，只记 `kind:edit` | `gates.js:37-42` |
| 无备份记录且 `autoBackup=true` | 先备份，再放行；结果里追加“已自动备份 …” | `gates.js:44-61`、`gates.js:144-156` |
| 无备份记录且 `autoBackup=false` | **拒绝**（返回字符串） | `gates.js:63-69` |
| 闸门内部抛异常 | 放行 + 写 `source:'backup-gate'` 错误账 | `gates.js:70-81` |

拒绝串同时包含：`leno-ledger: 未备份。`、规范化绝对路径、`ledger_backup {"file_path":"…"}` 可直接复制的补救调用。默认 `autoBackup=true` 时不会走到拒绝分支（S11）。

### 2.2 收工闸（`agent/turn-stopping`）

| 条件 | 行为 | 落点 |
|---|---|---|
| 当日存在 `接口\说\<today>-*.md` | 放行 | `gates.js:98` |
| 当日已有 `type:'skipped-check'` 错误账 | 放行 | `gates.js:99` |
| 同一 `turn` 已 steer 过 | 放行（防死循环） | `gates.js:101-103` |
| 无事件、无跳过、`payload.agent.steer` 可用 | `agent.steer({role:'user', …})` 把“下一步”塞回 inbox | `gates.js:120-125` |
| 无 `agent` / 无 `steer` | 写错误账后放行 | `gates.js:105-112` |
| 内部异常 | 写错误账后放行 | `gates.js:126-136` |

本实现不使用 abort/抛错：turn-stopping 是“可被劝阻”的边界，劝阻方式是 steering（见 `_probe` 中 agent-loop 与 api-catalog 的说明）。`reason` 固定以 `leno-ledger: 收工未记账。` 开头，并给出 A（写事件文件五栏）/B（`ledger_error {"text":"原因","skip_check":true}`）两条下一步。

### 2.3 判断闸（无发帖工具时的退化，S13）

| 条件 | 行为 | 落点 |
|---|---|---|
| `id` 既不是 `猜` 也不匹配 `^[ABC]\d+$` | 拒绝 | `tools.js:160-163` |
| `why/who/audience/approach/verbatim` 任一为空 | 拒绝 | `tools.js:164-168` |
| 四问齐全 | 写 criteria-log + beliefs-log；有 `rule` 时累加 usage | `tools.js:172-192` |

本环境未发现独立的发帖工具，因此 S13 的退化方案就是“四问必填 + 显式规矩引用”。

### 2.4 注入段（不是拦截，是提示）

| 条件 | 行为 | 落点 |
|---|---|---|
| 无未做 且 今日有事件 且 未结错误 <3 | 返回 `''`，段消失 | `inject.js:19` |
| 有未做 | 最多 4 条（含摘要共 ≤5 行），每条截 20 字，7 天内、24h 未注入 | `inject.js:24-30` |
| 无事件 | 追加一行“今日还没有 接口/说/…，收工会被拦” | `inject.js:37-39` |

| 注入内部异常 | 返回空段 + 错误账 | `inject.js:54-65` |

### 2.5 `ledger_error` 的跳过锁（S14 / 六问 6）

| 条件 | 行为 | 落点 |
|---|---|---|
| `level` 不在 P0/P1/P2 | 拒绝 | `tools.js:365-367` |

## 问 1：错误账没有对应的 `ledger_*` 工具

**方案**：新增第 7 个工具 `ledger_error`。
- 参数：`text`（必填）、`source`（记错来源，如 `"ledger_today"`）、`level`（`P0|P1|P2`，默认 `P1`）、`ref`（相关文件/行号，可选）。
- 写入 `whale-error-ledger.jsonl`，每行 `{t, text, source, level, ref}`。
- `ledger_today` 首行末尾追加聚合：未结错误 ≥3 条时显示 `⚠错误N`。
- 结论：规划书里"错误账"只有文件没有工具，属于漏项，用第 7 个工具补齐，不做隐藏副作用。

## 问 2：怎么计量"规矩被调用"

**方案**：不做行为检测（不可靠、易误判），改为**显式引用计量**。
- `ledger_judge` 增加 `rule` 参数（规矩 id，如 `发一条之前`）；每次下判断时记录 `whale-rule-usage.json`：`{rule: {n, last}` 与 `whale-criteria-log.jsonl`。
- `ledger_today` 显示"近 7 天被引用 0 次的规矩数"。
- **诚实边界**（必须写进报告）：这只统计"显式写了规矩 id 的判断"，不统计"心里想过没写"。所以只能降级为"引用率"指标，不能声称"规矩真被遵守"。

## 问 3：验收指标 4（7 天没被调用的规矩要简化）可被"退休刷低"

**方案**：规矩只许**合并**或**标记取代**，不许无痕删除。
- `ledger_belief` 增加操作 `retire`（退休）：必须带 `successor`（取代它的规矩 id）或 `mergeInto`；同时往 manifest 写 `kind: retired` 事件。
- 验收指标改为：**"7 天引用 0 次 且 未被标记取代"的规矩数**。退休但无 successor 的，单独列为"孤儿规矩"并报警。
- 效果：刷指标的唯一方式是把规矩真合并掉，而合并本身留下痕迹。

## 问 4：备份去重与"漏备"无法区分

**方案**：manifest 每条记录 `path + sha256 + size + mtime + kind`，用指纹而非路径判重。
- **去重**：同 path、同 sha256、当日已存在 → 返回 `dedup: true`，闸门放行。
- **漏备**：当日 manifest 无该 path 的任何记录 → 拒绝。
- **改过再改**：sha256 变化 → 视为新版本，必须再备（同一文件当日第 2 次修改仍要备份，不因"今天备过"而放行）。
- 结论：两者由 sha256 天然区分，不需要额外标记。

## 问 5：每轮注入变成噪声

**方案**：只注入"仍然成立且有信息量"的内容。
- 只取未做账中 7 天内新增的，最多 5 条，每条截断 20 字；
- 已注入过的记 `last_injected`，24h 内不重复注入同一条；
- 三项都正常（无未做、今日有事件、错误<3）→ 返回空段，系统提示里自动消失（S19）。
- 注入位置固定在尾部段（order ≥ 9000），不碰前缀，避免破坏缓存（S18）。

## 问 6：`--no-event` 逃生阀太方便，等于没有闸

**方案**：给逃生阀上三道锁。
1. 每次跳过都必须写错误账（`type: skipped-check`），可见、可数；
2. **每自然日最多 1 次**跳过；第 2 次仍无事件 → 拒绝收工，reason 提示"要么记账，要么改规矩"；
3. 阈值可配置（`maxSkipsPerDay`，默认 1），写进配置与报告。
- 结论：允许一次例外（真实场景需要），但不允许把例外变成常态。

## ⑤ 已知缺陷与未做（诚实清单）

### 5.1 环境/API 限制

1. **没有 `multi_edit`**：本版本 DSH 只暴露 `write` / `edit`。备份闸只拦这两个；将来若出现批量写工具，需扩展 `gates.js:20` 的白名单，否则会漏拦。
2. **没有发帖工具**：S13 要求的“发帖闸”没有可拦截的真实工具，退化为 `ledger_judge` 四问必填 + 显式 `rule` 引用。它只能拦住“调用 ledger_judge 却答不全四问”，拦不住绕过 ledger_judge 直接发帖。**这部分只能算部分满足**。
3. **turn-stopping 的取消机制只在 mock 中验证**：源码结论是“监听者 `agent.steer()` 把新消息塞回 inbox，回合再走一步”，不是 abort/抛错。本插件按此实现（`gates.js:120-125`），但**未在真实 DSH 回合里实测**是否真的再走一步、`turn` 是否按步递增（若按步递增，同一回合可能多次 steer；当前去重键是 `turn`，防不住这种情况）。真实行为**未验证**。
4. **注入段对真实系统提示的影响未实测**：S18 要求“实测影响写报告”。本插件只调用 `ctx.systemPrompt.section({ order: 10300 })`（v0.2 由 9500 后移，见 ⑦），mock 断言了段名、order、空串消失；但因为 S27 禁止启动服务，没有在真实会话里量化 token 与缓存影响。**未验证**。
5. **沙箱下 `node --test test/` 会 EPERM**：见 §4.1。测试本身全绿，但“原样命令”在本会话不可用。

### 5.1.1 闸的覆盖面（必须说清楚）

备份闸的覆盖面 = **模型级 `write` / `edit` 工具调用**。

`pwsh`（`Set-Content`、`Add-Content`、`Copy-Item`）、node 脚本、插件外部进程的写入**不经过 guard**，也不会自动备份或计入 `改N`。所以：

- `改N / 备M` 只统计“经过闸的动作”，不是当天全部文件改动；
- 用 shell 改文件时，需要手工调用 `ledger_backup {"file_path":"…"}` 补备份，账才对得上；
- 报告早期版本只提了 `multi_edit`，漏了这一条，属于表述缺口，在此更正。

（不把 `pwsh` 加进白名单：无法可靠判断一条 shell 命令是否写文件，误拒会直接废掉工作流。）

### 5.2 功能缺口

6. **错误账没有“结清”入口**：`unresolvedErrors()` 把所有 `type:'error'` 都算未结，没有任何工具能标记已解决。于是 `⚠错误N` 会单调增长；`ledger_today` 的“未结错误”实际是“历史错误”。六问没要求结清，这里如实列出。
7. **注入 24h 去重按“文本 sha256”而非条目 id**：两条完全相同的未做文本会共享冷却；`whale-undone.jsonl` 的既有行没有 id，无法更细粒度去重。
8. **单轮最多 4 条未做**：六问说“最多 5 条”，但 ≤5 行里还要放摘要行，所以实现取 4 条（`inject.js:29`），并未严格到 5 条。这是为满足 S17 的“≤5 行”做的取舍。
9. **新增规矩不写回 `whale-beliefs.md`**：该文件按规划书只读，新规矩落在 `whale-criteria/<id>.md`。两处真相可能分叉；`ledger_belief list` 合并了两边，但外部工具只读 beliefs.md 时会看不到新规矩。
10. **`kind:'retired'` 写在备份 manifest 里**：六问 3 明确要求写 manifest，照做；但语义上它和备份事件混在一张表，统计时要按 `kind` 过滤。
11. **时区只测了 Asia/Shanghai**：`dateInZone` 用 `Intl`，对 DST 时区在切换日的行为未测。
12. **网络盘/跨卷**：原子写用“同目录 tmp + rename”，避免跨卷；但在网络文件系统上 rename 的原子性未验证。
13. **`steeredTurns` 是内存 Set**：只增不减，长会话会缓慢增长；插件重载后丢失（可能对同一 turn 再 steer 一次）。
14. **`whale-beliefs-log.jsonl` 的损坏容错未单独测**：代码走同一条 `readJsonl`，但没有专门用例；只有 conflicts/undone 被覆盖。

### 5.3 未验证清单（不得当作已完成）

- 真实 DSH 会话中 `agent/turn-stopping` 的 steer 行为、以及“无事件 → 模型真的去写事件文件”的闭环。
- 真实系统提示中注入段的 token 占用、缓存命中影响。
- 真实 `write`/`edit` 工具经过 guard 后的拒绝呈现（`Error: <reason>`）在 GUI 里的实际样子；只用 mock exec 验证了返回字符串。
- 在沙箱外运行 `node --test test/`（多进程模式）。
- 发帖工具存在时的拦截（本环境没有该工具）。

## ⑥ 部署 / 卸载步骤（**未执行，由用户决定**）

### 6.1 部署

1. 确认 Node ≥ 22：`node --version`。
2. 把插件加入 desktop profile（**会改 `C:\Users\HUAWEI\.dsh\profiles\desktop\package.json`，本报告未执行**）：

   ```powershell
   dsh plugin --profile desktop add "link:F:\agent expore\dsh-leno-ledger\plugin"
   ```

   等价手工改法：在 `dependencies` 加
   `"dsh-leno-ledger": "file:F:/agent expore/dsh-leno-ledger/plugin"`，
   并在 `dsh.profile.bundles` 末尾加 `"dsh-leno-ledger"`。
3. 重启 DSH（关闭现有 Web 会话再开），确认 7 个 `ledger_*` 工具可见。
4. 首次启用会在 `DSH_HOME`（默认 `C:\Users\HUAWEI\.dsh`）下创建：
   `whale-conflicts.jsonl`、`whale-backup-manifest.jsonl`、`whale-error-ledger.jsonl`、
   `whale-criteria-log.jsonl`、`whale-rule-usage.json`、`whale-criteria\`、`backup\`。
   不会创建/覆盖 `whale-beliefs.md`。

### 6.2 卸载

```powershell
dsh plugin --profile desktop remove dsh-leno-ledger
```

然后重启 DSH。插件停用即撤销全部注册（`index.js:44-50`，测试 `S25`）。

数据文件**不会**自动删除；是否清理由用户决定。建议保留 `whale-*.jsonl` 与 `backup\` 以便回溯；如要彻底清理，先自行备份再删。

### 6.3 风险点

- 部署会改 profile 的 `package.json` 并触发依赖安装；本会话被禁止改 profile，故未执行。
- `dsh plugin add` 的具体参数以本机 `dsh plugin --help` 为准；上面命令按 `dsh-bili-whale/README.md:99` 的现有用法推导。
- 收工闸一旦生效，**每个没有 `接口/说/<date>-*.md` 的回合都会被 steer 一次**；如果模型不配合，可能反复出现“收工未记账”的提示。可用 `ledger_error skip_check:true` 跳过（每天 1 次），或调大 `maxSkipsPerDay`。
- 备份闸默认自动备份，会在 `~/.dsh/backup\<date>\` 下积累 `.bak`；没有自动清理策略。
- 首次启用后 `ledger_today` 可能因历史错误账立刻显示 `⚠错误N`（见 5.2 第 6 条）。
