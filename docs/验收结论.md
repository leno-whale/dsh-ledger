# 验收结论 v0.3（旧会话不受保护 → 可交付版）

日期：2026-10-27 00:1x　审核：主智能体（DeepSeek Harness）　实现：代码员子智能体（948e3124）

## 一、这次修的是什么

v0.2 在真实机器上 6 条功能全灭（0/6），问题书见 `docs/问题-旧会话不受保护-2026-10-26.md`。

**根因（已由源码证据坐实）**：`plugin/lib/index.js` 的插件对象没有声明 `inject`，`apply()` 里直接访问 `ctx.tools`。对照宿主 `dsh-tool-fs` 的写法（`const inject = ["tools","fs","systemPrompt","workingDirectory"]` 之后才用 `ctx.tools`），v0.2 的 `apply` 在 `store.ensureDirs()` 之后、注册工具之前抛 `TypeError`，于是：账文件建了、工具表没有、guard 没挂、注入没进、turn-stopping 没挂 —— 正好 0/6。

> **更正（2026-10-27 01:0x，主智能体）**：我 2026-10-26 21:19 判断「插件加载了，只是工具表在会话开始时建，所以新对话才有工具」——**这条是错的**。
> 真实的抛点在**注册工具之前**（`ctx.tools` 属性访问本身即抛），所以**从来没有任何会话拥有过这些工具**，不是「旧会话没有、新会话会有」。
> 纠正后的验证法：先跑 `plugin/tools/status.mjs` 看五段，再谈会话新旧。

## 三、只做到 mock 级、或没做到的（如实记）

- **S4（旧会话热挂）**：guard 是全局注册，但**已存在的会话要重启 DSH 才受保护**。插件侧在旧进程中无法把新代码换进去——这不是实现缺陷，是加载时机；README 第一屏已明说，用了「重启一次」而不是「仅新会话」。
- **S10 真实回合**：`agent.steer({id,role,content,source})` 的活会话行为未实测（只按宿主签名写、测试覆盖了调用与限流）。重启后第一次收工若没被拦，先跑 `status.mjs` 看 `turnStopping` 段是否 ok。
- **S5/S6 现场效果**：需部署后由主人实测一次「改已存在文件」——预期 backup 目录 +1、manifest 多两行（backup + change）。
- **S8 backfill 的语义边界**：补的是「当前内容的副本」，不是改前原件（离线拿不到原件）；默认 dry-run，重复跑幂等。
- `--test-isolation=none` 是当前沙箱禁子进程管道的绕行，普通机器 `node --test` 即可（未在沙箱外复跑）。
