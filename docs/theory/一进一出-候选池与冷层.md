## 一、现在的问题（都有数）

**进的那一头太松。** 2026-10-28 一天里，中层判据从 21 条涨到 26 条——B22「谁的话可以直接回」、B23「不翻电脑」、B24「私人信息硬线」、B25「怎么看片」、B26「署名」，全是**听完就写进去**的。架构里写的三态是 `candidate → accepted | rejected | expired`，实际执行是「想到即入」。

## 二、P5：𝔹₂ 候选池（进的那一头）

### 它是什么

新听来的一句话，**先进候选池，不进判据**。三态：

- `candidate`：记下了，但只出现过一次
- `accepted`：出现 ≥2 次，或带来了具体反例 → 升格成 $\mathbb B_1$
- `rejected` / `expired`：被明确否掉，或 30 天没动静 → 归档（不删）

### 怎么落地

1. `自我\候选\<id>.md`，一条一个文件，格式同判据，多一行 `seen: N` 与 `first: <日期>`
2. `ledger_belief add --cand` 写到这儿；再被提及时 `seen++` 并追加一行「第 N 次：谁、什么时候、原话」
3. 触发升格的只有两种：`seen ≥ 2`，或**这次带来了一个具体反例**（不是「我觉得不对」，是「照它做，X 出了错」）
4. `expired` 判据：`first` 超过 30 天、且 `seen = 1` → 移入 `自我\归档\候选过期\`，文件名保留

### 测试标准（七层）

- **T1 门必须硬**：`ledger_belief add` 不带 `--cand` 时，若该条从未在候选池出现过（`seen < 2`）且没带反例 → **拒绝直接写入 $\mathbb B_1$**，并提示「先进候选」。
- **T2 只追加**：`seen++` 与「第 N 次」是追加行；已存在的内容逐字不改（前 N 行 sha256 不变）。
- **T3 幂等**：同一条在同一天被提到两次，`seen` 只 +1（键＝日期 + 原文前 24 字），避免「同一句话顶两次就升格」。
- **T4 坏行容错**：候选文件里有一行坏 JSON/坏格式，不清空、不崩，其余条目照常可读，并在 `ledger_today` 里报「候选池有 N 条坏行」。
- **T5 不进注入**：`build-i1.mjs` 只读 $\mathbb B_0$、已接受的判据、触发器——**候选池里的东西一个字都不进 $I_1$**。
- **T6 可溯源**：升格后那条判据的 `src` 必须能翻回候选文件与其「第 N 次」的出处（谁的哪句话）。
- **T7 反例测试**：写一条 `seen=1` 且无任何「第 N 次」的候选，直接调升格 → **必须失败**。这条测试是防止我把门重新放松。

### 怎么知道成了

池子里 ≥1 条，并且**真的走完一次「候选 → 升格」**（不是手工搬过去的，是 `seen` 到了 2 自己提示的）。

## 三、P6：$L_3$ 冷层分册（出的那一头）

### 它是什么

把「当季在写的」和「已经沉下去的」分开：**当季一个文件，旧季只读**。

### 怎么落地

1. 目标布局：`自我\冷\diary-2026Q4.md`、`自我\冷\lessons-2026Q4.md`、`自我\冷\diary-private-2026Q4.md`
2. 当季继续写在**当前文件**里；跨季（季度第一天第一次写）时，把上一季整块切走，旧文件设为只读
3. **留一张索引行**：`自我\冷\索引.md`，一行一条「2026Q4 → diary-2026Q4.md（2026-10-01 ~ 2026-12-31）」。**这是防「页码链断掉」的唯一办法**——汐那句话：「跨两天的事，第二天那页第一句写『（接昨天那件 X）』」，跨季同理。
4. `query.mjs` 加 `--cold`：按关键词查冷层，返回「文件 + 行号 + 那一行原文」
5. `build-i1.mjs` **永不读冷层**（硬约束，写进代码注释与测试）

### 测试标准（七层）

- **T1 旧文件只读**：切分后旧文件 sha256 不变（前后比对），程序也拒绝再写入旧文件。
- **T2 行数守恒**：切分前后总行数一致（旧 + 新 = 切分前），**不丢不重**；随机抽 20 行逐字比对。
- **T3 边界确定**：季度第一天写新文件、最后一天写旧文件；用固定时间戳测两次，结果一致（不许「看今天巧合」）。
- **T4 编码容错**：切分时遇到 BOM、CRLF、空行，不改变内容字节（只搬不改）。
- **T5 注入不变**：`build-i1.mjs` 的输出字节数**不随冷层增长而变**（写一条假冷层 100 KB，注入字节数不动）。
- **T6 可查**：`query --cold "关键词"` 能命中，并给出文件与行号；查不到时明确说「没查到」，不静默返回空。
- **T7 反例测试**：把冷层并回热层（删掉分册、把内容塞回当季文件）→ 必须有一条测试**变红**。这条是防止「为了省事又搬回来」。

### 怎么知道成了

本季一个文件、**总字数与今天持平**（不是继续涨）；`query --cold` 能翻到去年的旧事并给出位置。

## 四、两件事共用的三条纪律

1. **只搬不改**：切分、归档、过期，全都是「换个地方放」，不许顺手改写内容（要改另开一次操作，并留原件）。
2. **动作要有出口**：候选过期、冷层切分，都要在 `ledger_today` 或收工四问里留一行——**没有出口的机制，三周后就没人在做了**。
3. **先有测试再动手**：这两个机制都会「悄悄坏」（候选悄悄没排队、冷层悄悄没切），没测试的坏法是静默的。

## 附：为什么先把标准写下来

这两件事都属于「看起来做了、其实没做」的类型：候选池可以建个空目录就叫「有了」，冷层可以搬完文件就叫「分了」。

**标准写在代码前面，是为了让「没做」也能被看出来。**
